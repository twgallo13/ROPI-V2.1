4. LAUNCH CALENDAR SIGNUP FLOW
--------------------------------------------------------------------------------

From Launch Calendar Pages (27e45ee1ec5a81ecac18fa5c2bf3842e, 29745ee1ec5a80be8b83f113074a1837)

Public Launch Calendar (/) Behavior:
- URL: / (root route, public access)
- Shows upcoming product launches in calendar/list view
- Each launch has "NOTIFY ME" CTA button
- When unauthenticated user clicks "NOTIFY ME":
  1. Open SignInModal
  2. User signs in with Google or Email/Password
  3. Modal closes, signup action completes automatically
  4. Show confirmation: "You're in. We'll notify you about this launch."
- When authenticated user clicks "NOTIFY ME":
  1. Write to Firestore immediately (no modal)
  2. Show confirmation: "You're in. We'll notify you about this launch."

Internal Launch Calendar (/launch-calendar) Behavior:
- URL: /launch-calendar (internal app route, requires auth)
- Same signup mechanism as public page
- Additional admin features (create/edit launches - future scope)
- Show "Sign up / Sign in to join launches" action if not authenticated

Firestore Collection: launchSignups
- Document ID: `${launchId}_${currentUser.uid}` (composite key)
- Fields:
  {
    launchId: string,         // e.g., "launch_2025_q1_ropi_runner"
    userUid: string,           // Firebase user UID
    email: string,             // User's email for notifications
    createdAt: Timestamp,      // Signup timestamp
    source: string,            // "aoss-staging" (env identifier)
  }
- Idempotent writes (doc ID prevents duplicates)
- No update/delete logic (one signup per user per launch)

Centralized Logic:
- Create useLaunchSignup hook in packages/web/src/hooks/useLaunchSignup.ts
- Interface:
  ```typescript
  interface UseLaunchSignupReturn {
    signupForLaunch: (launchId: string) => Promise<void>;
    isSignedUp: (launchId: string) => boolean;
    loading: boolean;
    error: string | null;
  }
  ```
- Check authentication state from useAuth()
- If !currentUser: Open SignInModal, defer signup until authenticated
- If currentUser: Write to Firestore immediately

6. FIREBASE AUTH CONFIGURATION
--------------------------------------------------------------------------------

Firebase SDK:
- Use modular SDK: firebase/auth (already in package.json)
- Initialize in firebaseConfig.ts (already exists for Firestore/Storage)
- Export auth instance

AuthProvider Implementation:
- Context location: packages/web/src/contexts/AuthProvider.tsx (create new)
- Interface:
  ```typescript
  interface AuthContextValue {
    currentUser: User | null;           // Firebase User object
    isAdmin: boolean;                   // Computed from metadata/admins
    loading: boolean;                   // Auth initialization state
    signInWithGoogle: () => Promise<void>;
    signInWithEmail: (email: string, password: string) => Promise<void>;
    signUpWithEmail: (email: string, password: string) => Promise<void>;
    signOut: () => Promise<void>;
  }
  ```

AuthProvider Logic:
- Subscribe to onAuthStateChanged in useEffect on mount
- On auth state change:
  1. Update currentUser
  2. If user exists: Read metadata/admins from Firestore
  3. Check if user.email in admins.emails array
  4. Set isAdmin boolean
  5. Set loading=false
- Handle errors gracefully (console.warn, don't crash)
- Unsubscribe on unmount

SignUpWithEmail Flow:
- Call createUserWithEmailAndPassword(auth, email, password)
- On success: Send email verification
  await sendEmailVerification(auth.currentUser!)
- Show message: "Verification email sent. Please check your inbox."
- User must verify email before full access (future: add verification gate)

Required Rule Addition for launchSignups:
```
match /launchSignups/{signupId} {
  // Allow authenticated users to create their own signups
  allow create: if request.auth != null
                && request.resource.data.userUid == request.auth.uid
                && request.resource.data.keys().hasAll(['launchId', 'userUid', 'email', 'createdAt', 'source']);
  
  // Allow users to read their own signups
  allow read: if request.auth != null
              && resource.data.userUid == request.auth.uid;
  
  // No updates or deletes (signups are immutable)
  allow update, delete: if false;
}
```
