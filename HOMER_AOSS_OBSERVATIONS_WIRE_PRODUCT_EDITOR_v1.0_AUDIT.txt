TECHNICAL ARCHITECTURE
================================================================================

Data Flow:
1. ProductEditorPage renders with product.id
2. ObservationsPanel receives productId prop
3. useEffect calls listenToObservations(productId, callback)
4. Firestore listener fires callback with observations array
5. Component state updates via setObservations()
6. UI re-renders with new observations

Real-time Updates:
- Firestore listener established in useEffect
- Callback fires whenever observations collection changes
- State automatically updates, triggering re-render
- Works across multiple browser tabs (real-time sync)

Offline Mode:
- isFirebaseAvailable() checks if Firestore initialized
- If false, component shows offline banner
- localStorage used as fallback storage
- "Retry Sync" button calls syncLocalToFirestore()

Image Upload:
- Multiple file selection supported via input[type="file"]
- Files stored in state as File[] array
- Preview generation via FileReader.readAsDataURL()
- Upload handled by addObservation() service function
- Service attempts Storage upload, falls back to data URL if offline

Scroll-to-Field:
- Linked field stored as string (e.g., "attributes.color")
- Click handler searches DOM for element with name="[field]"
- Falls back to data-field="[field]" attribute
- Calls scrollIntoView({ behavior: 'smooth', block: 'center' })
- Adds .field-highlight class for 2s yellow pulse animation

Permissions:
- useUser() hook provides current user context
- User passed to addObservation() and resolveObservation()
- Resolve button shows creator name in tooltip
- TODO: Add server-side role checks for resolve permissions

================================================================================
LESSONS LEARNED
================================================================================

1. Component Rewrite Strategy
   - Complete rewrite more efficient than incremental modifications
   - Clear separation of concerns (props → productId only)
   - Self-contained components easier to test and maintain

2. Test Simplification
   - Smoke tests sufficient when service layer fully tested
   - Component tests should focus on integration, not logic
   - Avoid complex async test scenarios with mocked real-time listeners

3. TypeScript Imports
   - Remove unused imports immediately to avoid build errors
   - TypeScript strict mode catches these during compilation
   - Better to fix during implementation than at build time

4. Real-time Listener Pattern
   - useEffect cleanup function essential for unsubscribe
   - Firestore listeners work automatically across tabs
   - No need for polling or manual refresh

5. Offline Mode Detection
   - isFirebaseAvailable() centralizes offline detection
   - localStorage fallback seamless for users
   - Sync button provides clear path back to online mode

6. Image Upload UX
   - Multiple file support better than single image
   - Preview generation essential before upload
   - Fallback to data URL prevents upload failures

7. Scroll-to-Field Implementation
   - DOM querying with multiple strategies (name, data-field) more robust
   - CSS animations more performant than JavaScript
   - scrollIntoView() smooth behavior provides better UX
