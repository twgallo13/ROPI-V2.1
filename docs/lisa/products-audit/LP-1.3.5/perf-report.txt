## API Performance Characteristics

### Products List Endpoint

| Scenario | Expected Latency | Notes |
|----------|-----------------|-------|
| Simple list (no filters) | <100ms | Direct Firestore query |
| With single filter | <150ms | Firestore query + client sort |
| With multiple filters | <200ms | Requires all filters to match |
| With search query | <300ms | Client-side filtering |
| With date range | <250ms | Client-side date comparison |
| Combined filters + search | <500ms | Full client-side processing |

### Pagination Behavior

| Config | Docs Fetched | Memory Impact |
|--------|--------------|---------------|
| No filters | limit + 1 | Minimal |
| With filters/search | Up to 500 | Moderate |

## Recommendations

### For Small Catalogs (<500 products)
- Current implementation is sufficient
- Client-side filtering acceptable
- All operations should complete <500ms

### For Medium Catalogs (500-2000 products)
1. Deploy Firestore composite indexes
2. Reduce fetchLimit to 200
3. Implement proper cursor pagination

### For Large Catalogs (>2000 products)
1. Migrate search to Algolia/Elasticsearch
2. Implement server-side pagination with cursors
3. Add caching layer for common queries
4. Consider denormalizing filter fields
