## Changes Summary

### 1. normalizeFieldPath Middleware (NEW)
**Path:** `packages/api/src/middleware/normalizeFieldPath.ts` (357 lines)

**Purpose:** Canonicalizes Smart Rule field paths on write operations to ensure `attributes.` prefix

**Key Functions:**
- `normalizeFieldPath()` - Normalizes single field path
- `normalizeSmartRuleFields()` - Normalizes entire rule (action + conditions)
- `normalizeFieldPathMiddleware()` - Express middleware (not yet wired to HTTP endpoints)
- `validateCanonicalFieldPath()` - Validates field is in canonical form

**Allowed Prefixes:**
```typescript
['attributes.', 'observation.', 'meta.']
```

**Normalization Rules:**
1. If already has allowed prefix → return as-is
2. If matches known attribute ID → prefix with `attributes.`
3. If is system field → reject (requires explicit prefix)
4. If not resolvable → return error

**Examples:**
- `gender` → `attributes.gender` ✅
- `rics_category` → `attributes.rics_category` ✅
- `gender.value` → `attributes.gender.value` ✅
- `attributes.gender` → unchanged ✅
- `unknown_attr` → ERROR ❌

### 2. Server-Side Schema Validation (MODIFIED)
**Path:** `packages/api/src/schemas/smartRuleSchema.ts` (235 lines, +235 additions)

**Purpose:** Enhanced validation with Firestore registry integration

**New Functions:**
- `validateSmartRuleServer()` - Full server validation with registry
- `validateActionAgainstRegistry()` - Validate action fields and values
- `validateConditionAgainstRegistry()` - Validate condition fields
- `extractAttributeId()` - Extract attribute from canonical path

**Validation Flow:**
```
1. Basic schema validation (Zod)
2. Field path normalization
3. Registry constraint validation
   - Check attribute exists
   - Check not internal-only
   - Validate enum values
```

**Error Codes:**
- `INVALID_TARGET_FIELD` - Unknown or invalid target field
- `INVALID_CONDITION_FIELD` - Unknown condition field
- `INVALID_ENUM_VALUE` - Value not in allowed_values
- `INTERNAL_ONLY_FIELD` - Cannot target internal-only attribute
- `SCHEMA_VALIDATION` - Basic Zod schema failure
- `NORMALIZATION_FAILED` - Field normalization failed

## Technical Notes

### Allowed Prefixes
```typescript
const ALLOWED_PREFIXES = ['attributes.', 'observation.', 'meta.'];
const SYSTEM_FIELDS = ['tags', 'source', 'sku', 'name', 'description'];
```

- `attributes.*` - Product attributes (primary use case)
- `observation.*` - Observation/import data
- `meta.*` - Metadata fields
- `source.*` - Import source fields (allowed in conditions only)

### Registry Lookup Precedence
1. Exact match in Firestore registry
2. Match by `attribute_id`
3. Match by short name (e.g., `gender` for `attributes.gender`)

If no match found → `INVALID_TARGET_FIELD` error

### Audit Trail
Migrations and rule writes create audit entries in:
- Collection: `settings/smartRules/audit`
- Document ID: `migration_<timestamp>_<ruleId>` or `audit_<timestamp>_<random>`
- Fields: `ruleId`, `action`, `actor`, `timestamp`, `changes` (before/after)

### Migration Safety
- **Dry-run default:** Requires explicit `--apply` to make changes
- **Backup:** Exports JSON backup to `backups/smart-rules-backup-<timestamp>.json`
- **Idempotent:** Running apply twice is no-op (only normalizes what needs it)
- **Flags:** Unknown fields flagged to `settings/smartRules/migration_flags/{ruleId}`
