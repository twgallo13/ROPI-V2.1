### 3. Workflow Updates ✅

#### Updated: Run set-admin script step

**Before**:
```yaml
- name: Run set-admin script
  env:
    GOOGLE_APPLICATION_CREDENTIALS: /tmp/sa.json
    EMAIL: "${{ github.event.inputs.email }}"
  run: |
    node -e "const admin=require('firebase-admin'); \
      admin.initializeApp({ credential: admin.credential.applicationDefault(), projectId:'ropi-bccee' }); \
      (async ()=>{ const u = await admin.auth().getUserByEmail(process.env.EMAIL); \
        await admin.auth().setCustomUserClaims(u.uid, { admin: true }); \
        console.log('Set admin claim for', process.env.EMAIL); \
      })().catch(e=>{ console.error(e); process.exit(1); });"
```

**Issues with old approach**:
- Required `firebase-admin` package (not installed, would cause MODULE_NOT_FOUND)
- Inline code harder to maintain and test
- No proper error handling
- Not using production-ready script

**After**:
```yaml
- name: Run set-admin script
  env:
    GOOGLE_APPLICATION_CREDENTIALS: /tmp/sa.json
    EMAIL: "${{ github.event.inputs.email }}"
    FIREBASE_API_KEY: ${{ secrets.VITE_FIREBASE_API_KEY || secrets.FIREBASE_API_KEY || '' }}
  run: |
    set -euo pipefail

    echo "Confirm GOOGLE_APPLICATION_CREDENTIALS: $GOOGLE_APPLICATION_CREDENTIALS"
    echo "Active gcloud account:"
    gcloud auth list --filter=status:ACTIVE --format="value(account)"
    echo "Using project:"
    gcloud config get-value project || true

    # Ensure Node/npm available (ubuntu runner has Node, but ensure)
    if ! command -v node >/dev/null 2>&1; then
      echo "Installing Node..."
      sudo apt-get update -y
      sudo apt-get install -y nodejs npm
    fi

    # If there's a scripts/package.json, install deps (safe no-op otherwise)
    if [ -f scripts/package.json ]; then
      (cd scripts && npm ci --unsafe-perm)
    fi

    # Run the repo script (it performs token lookup + claims)
    node scripts/set-admin-custom-claim.js "${{ github.event.inputs.email }}"
```

**Improvements**:
1. ✅ Calls production-ready repository script
2. ✅ No external dependencies needed (script uses core modules only)
3. ✅ Checks for Node.js installation
4. ✅ Conditionally installs dependencies if `scripts/package.json` exists
5. ✅ Passes email as command-line argument
6. ✅ Pre-flight verification of gcloud state
7. ✅ Proper error handling with `set -euo pipefail`

## Repository Script Details

**File**: `scripts/set-admin-custom-claim.js`

**Dependencies**: None (uses only Node.js core modules)
- `https` - for REST API calls
- `child_process` - for executing gcloud commands
- `util` - for promisify

**How it works**:
1. Takes email or UID as command-line argument
2. Executes `gcloud auth print-access-token` to get OAuth token
3. Looks up user by email using Firebase Auth REST API
4. Sets custom claim `{ "role": "admin" }` via REST API
5. Returns exit code 0 on success, 1 on failure

**Why this is better**:
- No firebase-admin package needed (avoids MODULE_NOT_FOUND)
- Production-ready with proper error handling
- Uses Firebase Auth REST API directly
- Leverages gcloud authentication already set up
- Can be tested locally and in CI

## Troubleshooting

### If "MODULE_NOT_FOUND" error occurs:
**Should NOT happen anymore** - the script uses only core Node modules.

If it does occur, check:
- Script path is correct: `scripts/set-admin-custom-claim.js`
- Script file exists in repository
- Script doesn't have any `require()` statements for external packages

### If "gcloud: command not found":
- Setup gcloud step should have installed it
- Check logs from "Setup gcloud & activate service account" step

### If "permission denied" executing script:
- Script has execute permissions (`chmod +x` applied in repo)
- Ubuntu runner should be able to execute with `node scripts/...`

### If script fails with API error:
- Check gcloud authentication is active
- Verify service account has Firebase Auth permissions
- Check `GOOGLE_APPLICATION_CREDENTIALS` is set correctly
- Review script output for specific API error details

## Technical Notes

### Why Repository Script vs Inline Code

**Repository script advantages**:
1. **No dependencies**: Uses only Node.js core modules
2. **Testable**: Can run locally and in CI
3. **Maintainable**: Proper file structure, comments, error handling
4. **Production-ready**: Developed and tested in PROMPT_018C_vB
5. **REST API**: Direct Firebase Auth REST API calls (no SDK overhead)

**Inline code disadvantages**:
1. **Dependencies**: Requires firebase-admin (not available in runner)
2. **Hard to test**: Can't easily test inline code
3. **Hard to maintain**: Changes require workflow file edits
4. **Error handling**: Limited in one-liner format

### Environment Variables

The script uses these environment variables:
- `GOOGLE_APPLICATION_CREDENTIALS`: Path to service account JSON (set by workflow)
- `EMAIL`: Target user email (set by workflow from input)
- `FIREBASE_API_KEY`: Optional, for API key validation (from secrets)

The script gets OAuth token via:
```javascript
const { stdout } = await execAsync('gcloud auth print-access-token');
const accessToken = stdout.trim();
```

This relies on the "Setup gcloud & activate service account" step having run successfully.
