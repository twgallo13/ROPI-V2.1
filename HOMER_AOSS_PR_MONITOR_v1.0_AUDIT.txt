EXECUTIVE SUMMARY
================================================================================

AOSS_PR_MONITOR_v1.0 implements a comprehensive, safe, and automated PR 
monitoring and auto-merge system for the `aoss-main` branch. The system:

✅ Monitors PRs every 10 minutes + on PR events
✅ Auto-merges PRs when ALL safety criteria are met
✅ Integrates with existing Deploy AOSS Staging workflow
✅ Updates Notion Build Progress Log on merge
✅ Provides multiple opt-out mechanisms
✅ Includes comprehensive error handling and logging
✅ Posts helpful feedback comments to PRs

This implementation fulfills the mandate to "automatically monitor and safely
auto-merge PRs targeting aoss-main, then deploy aoss-main to staging."

IMPLEMENTATION OVERVIEW
================================================================================

Architecture
------------
- Single GitHub Actions workflow: `.github/workflows/pr-monitor-auto-merge.yml`
- Trigger mechanisms:
  * Scheduled: Every 10 minutes via cron
  * Event-driven: PR opened, synchronized, reopened, labeled, unlabeled, ready_for_review
  * Manual: workflow_dispatch for testing
- Integration with existing Deploy AOSS Staging workflow (no modifications needed)
- Notion API integration for Build Progress Log updates

Key Features
------------
1. **Comprehensive Safety Checks**
   - Validates mergeable state (no conflicts)
   - Verifies all required status checks pass
   - Confirms required approvals satisfied
   - Detects and blocks on "Changes Requested" reviews
   - Respects branch protection rules

2. **Smart Filtering**
   - Skips draft PRs
   - Skips PRs with manual-merge or no-automerge labels
   - Only processes PRs targeting aoss-main

3. **Transparent Operations**
   - Posts detailed comments on merge success
   - Posts helpful feedback on blocked PRs (conflicts, failed checks)
   - Logs all decisions to workflow output
   - Updates Notion Build Progress Log

4. **Error Resilience**
   - Handles merge failures gracefully
   - Posts error details to PR and Notion
   - Continues processing other PRs even if one fails
   - Non-blocking for deployment workflow

================================================================================
AUTO-MERGE SAFETY CRITERIA (MANDATORY GATES)
================================================================================

A PR will ONLY be auto-merged when ALL of these conditions are TRUE:

1. ✅ Base Branch Check
   - PR.base.ref === 'aoss-main'
   - Ensures only aoss-main PRs are processed

2. ✅ Draft Status Check
   - PR.draft === false
   - Skips all draft PRs

3. ✅ Label Check
   - PR does NOT have 'manual-merge' label
   - PR does NOT have 'no-automerge' label
   - Provides manual override mechanism

4. ✅ Mergeable State Check
   - PR.mergeable === true
   - PR.mergeable_state === 'clean'
   - No merge conflicts exist

5. ✅ Status Checks Validation
   - All check_runs.status === 'completed'
   - All check_runs.conclusion === 'success'
   - Combined status !== 'pending', 'failure', or 'error'
   - Ensures CI/CD passes

6. ✅ Approval Requirements
   - Reads branch protection API for required_approving_review_count
   - Counts APPROVED reviews (latest per user)
   - Approval count >= required count
   - Ensures code review standards met

7. ✅ Changes Requested Check
   - No reviews with state === 'CHANGES_REQUESTED'
   - Blocks merge if reviewer requested changes

OPT-OUT MECHANISMS
================================================================================

Multiple ways for developers to prevent auto-merge:

Method 1: Draft PR
------------------
- Convert PR to draft status
- Auto-merge skips ALL draft PRs
- UI: PR page → "Convert to draft" button

Method 2: Labels
----------------
- Add 'manual-merge' label to PR
- Add 'no-automerge' label to PR
- Auto-merge skips PRs with these labels
- UI: PR page → Labels → Add label

Method 3: Disable Workflow
--------------------------
- Go to Actions → pr-monitor-auto-merge.yml
- Click "..." → "Disable workflow"
- Disables auto-merge system entirely

Method 4: Changes Requested
---------------------------
- Request changes in PR review
- Auto-merge blocks until review updated/dismissed

ERROR HANDLING & EDGE CASES
================================================================================

Edge Case 1: Merge Conflicts
-----------------------------
Detection: PR.mergeable === false
Action: 
  - Skip auto-merge
  - Post comment: "Auto-merge blocked: PR has merge conflicts"
  - Instruct developer to rebase/update branch
Resolution: Developer resolves conflicts, pushes, monitor re-evaluates

Edge Case 2: Failed CI Checks
------------------------------
Detection: check_runs.conclusion !== 'success'
Action:
  - Skip auto-merge
  - Wait for checks to pass
  - No comment (developer can see failed checks)
Resolution: Developer fixes issues, pushes, checks re-run, monitor re-evaluates

Edge Case 3: Missing Approvals
-------------------------------
Detection: approval_count < required_approving_review_count
Action:
  - Skip auto-merge
  - Wait for approvals
  - No comment (developer can see pending reviews)
Resolution: Reviewers approve, monitor re-evaluates

Edge Case 4: Changes Requested
-------------------------------
Detection: reviews.some(r => r.state === 'CHANGES_REQUESTED')
Action:
  - Block auto-merge
  - Wait for review update
Resolution: Developer addresses feedback, reviewer approves or dismisses review

Edge Case 5: Merge API Failure
-------------------------------
Detection: github.rest.pulls.merge() throws error
Action:
  - Post comment with error details
  - Update Notion with failure
  - Log to workflow output
  - Continue to next PR
Resolution: Check GitHub permissions, branch protection rules, or merge manually

Edge Case 6: Branch Protection Issues
--------------------------------------
Detection: getBranchProtection() fails or returns unexpected rules
Action:
  - Log error
  - Use safe defaults (require 0 approvals)
  - Proceed with other checks
Resolution: Review branch protection settings, ensure API access

Edge Case 7: Missing Secrets
-----------------------------
Detection: GCP_SA_KEY_BASE64 not set (caught by deploy-staging.yml)
Action:
  - Deploy workflow fails (not PR Monitor's responsibility)
  - Error visible in deploy workflow logs
Resolution: Add GCP_SA_KEY_BASE64 to staging environment

Edge Case 8: NOTION_TOKEN Missing
----------------------------------
Detection: env.NOTION_TOKEN is undefined
Action:
  - Auto-merge proceeds normally
  - Notion update skipped
  - Log: "NOTION_TOKEN not set, skipping Notion update"
Resolution: Optional - add NOTION_TOKEN secret for Notion integration
