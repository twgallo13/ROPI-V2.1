================================================================================
TECHNICAL ARCHITECTURE
================================================================================

COMPONENT HIERARCHY:

ImportManagerPage (Main coordinator)
├── ImportUploadStep (Step 1: CSV file upload)
├── ImportMappingStep (Step 2: Header → attribute mapping)
├── ImportPreviewStep (Step 3: Normalized data preview with validation)
├── ImportConfirmStep (Step 4: Backend API call)
└── ImportHistoryTable (Display recent import_batches)

ImportBatchDetailPage (Standalone page)
└── Batch metadata + row-level error details

ROUTING:
- /import → ImportManagerPage (gated: admin + merch)
  - Query params for step: ?step=upload|mapping|preview|confirm
  - Default view: history table
- /import/batches/:batchId → ImportBatchDetailPage (gated: admin + merch)

DATA FLOW:

1. Upload Step:
   Input: File selection
   Output: { file: File, data: string[][], headers: string[] }
   Library: PapaParse 5.5.3 for CSV parsing

2. Mapping Step:
   Input: CSV headers from step 1
   Process: Auto-match using DEFAULT_COLUMN_MAPPINGS (lowercase comparison)
   Output: { [csvHeader: string]: normalizedField | 'skip' }
   Validation: Ensures required fields (id, description) are mapped

3. Preview Step:
   Input: CSV data + mapping from steps 1 & 2
   Process: 
     - normalizeImportRow() for each preview row
     - validateImportRow() for validation status
   Output: Preview grid with raw/normalized/validation columns
   Display: First 10 rows with expandable error details

4. Confirm Step:
   Input: File + mapping config
   API Call: POST /api/importCSV
     - FormData with file upload
     - Bearer token from AuthProvider
     - columnMapping JSON in request body
   Output: batchId, auto-navigate to /import/batches/:batchId

BACKEND INTEGRATION:
- Import Engine API: /api/importCSV (from PROMPT_019A_vA)
- Firestore collections:
  - import_batches: Batch metadata
  - import_batches/{batchId}/rows: Row-level data with errors
- SDK imports:
  - DEFAULT_COLUMN_MAPPINGS: Auto-suggestion config
  - normalizeImportRow(): Attribute normalization
  - validateImportRow(): Field validation
  - ImportBatch, ImportEngineRow types

AUTH & ROLE GATING:
- AuthProvider context provides:
  - user: Firebase User object
  - customClaims: { admin?: boolean, merch?: boolean }
  - getIdToken(): Bearer token for API calls
- Access control:
  - hasWriteAccess = customClaims.admin || customClaims.merch
  - Guards routes with conditional rendering
  - Disables action buttons when !hasWriteAccess

```typescript
// API call
const idToken = await getIdToken();
const formData = new FormData();
formData.append('file', file);
formData.append('columnMapping', JSON.stringify(mapping));

const response = await fetch(`${apiUrl}/importCSV`, {
  method: 'POST',
  headers: { Authorization: `Bearer ${idToken}` },
```

- Endpoint: POST /api/importCSV

- Response: { batchId: string, rowCount: number, status: string }

Error Handling:
- Network errors: Show error message with retry
- Auth errors: Redirect to sign-in

NOTES & OBSERVATIONS

IMPLEMENTATION NOTES:

1. Component Organization:
   - All import-related components in packages/web/src/components/import/
   - Clear separation of concerns (one step per component)
   - Shared CSS patterns across all components
   - Consistent prop interfaces (callbacks for navigation)

2. State Management:
   - ImportManagerPage holds all state (file, data, mapping, preview)
   - Step components are controlled (no internal state)
   - Makes testing easier (pure functions)
   - Facilitates step navigation (back/forward)

3. Validation Strategy:
   - Client-side validation for UX (preview step)
   - Server-side validation for data integrity (backend)
   - Validation results stored in Firestore rows
   - Allows retry without re-upload

4. Performance Considerations:
   - PapaParse configured for streaming (large files)
   - Preview limited to 10 rows (configurable)
   - Firestore queries limited to 20 batches
   - FormData upload handles files up to 10 MB

5. User Experience:
   - Clear step indicators (breadcrumb-style)
   - Inline validation messages (immediate feedback)
   - Progress indicators (upload, processing)
   - Auto-navigation on success (reduced clicks)
   - Back buttons on all steps (easy correction)

DESIGN DECISIONS:

1. Why PapaParse?
   - Lightweight (30 KB gzipped)
   - Robust CSV parsing (handles edge cases)
   - Streaming support (large files)
   - Wide adoption (reliable)

2. Why 4-Step Flow?
   - Clear mental model (upload → map → preview → confirm)
   - Allows correction at each stage
   - Matches user expectations from Import Settings spec
   - Reduces errors (validation before commit)

3. Why Query Params for Steps?
   - Allows bookmarking/sharing of specific step
   - Browser back button works correctly
   - Preserves state on page refresh (if implemented)
   - Standard React Router pattern

4. Why Firestore for History?
   - Real-time updates (easy to add)
   - Scalable (handles large batch lists)
   - Consistent with rest of app (products, observations)
   - No additional backend API needed

SECURITY NOTES:

1. Auth checks in multiple layers:
   - Route guard (ImportManagerPage hasWriteAccess)
   - Backend API validation (Firebase Auth)
   - Firestore rules (admin/merch roles)

2. File upload security:
   - Size limit (10 MB)
   - Type validation (.csv only)
   - Backend validation (duplicate)
   - No direct file path exposure

3. API security:
   - Bearer token authentication
   - Token refresh on expiry (handled by AuthProvider)
   - CORS configured on backend (staging/production only)
