   - `allow create: if request.auth != null && ...` (authentication REQUIRED)
   - `allow update: if request.auth != null && ...` (authentication REQUIRED)

2. **Products Collection**:
   - `allow read, write: if request.auth != null` (authentication REQUIRED)

   - `allow read, write: if false` (deny all other collections)

**Critical Finding**: ALL Firestore operations require `request.auth != null`
- Unauthenticated clients are blocked from reading/writing
- No anonymous access configured
- No public read rules

**Why ropi-aoss-staging Fails**:
1. Dummy API key → Firebase Auth initialization fails
2. No authenticated user → `request.auth` is `null`
3. Firestore rules reject all operations → Permission denied errors
4. App falls back to localStorage-only mode

**Why ropi-bccee.web.app Succeeds**:
- Valid API key → Firebase Auth initializes successfully
- Even without explicit sign-in, Firebase SDK can make authenticated requests
  (if auth state persists from previous session or anonymous sign-in is triggered)
