## Findings

### Issue 1: ExportReadinessPanel Still Rendered
The legacy `ExportReadinessPanel` is still rendered in ProductEditorPage.tsx:200
alongside the new `CompletionExportGatePanel` (line 186).

This creates **two different export readiness indicators** that may show
conflicting information:
- ExportReadinessPanel shows legacy `product.exportReadiness.overall`
- CompletionExportGatePanel shows API-driven `completion.ready`

### Issue 2: ExportReadinessPanel Uses Different Data Source
- Legacy: `product.exportReadiness` (document field, local computation)
- New: API call to `/api/products/{id}/completion` (server-side evaluation)

### Issue 3: auth token bug affects both new panels
Both `CompletionExportGatePanel` (line 54) and `ExportPage` (line 36) use:
```typescript
Authorization: `Bearer ${localStorage.getItem('firebase_token') || ''}`
```
This key is never set (see Task 1), causing 401 errors.

---

## Recommendation (for follow-up LP)

1. **Remove ExportReadinessPanel** from ProductEditorPage.tsx:200-204
   - It shows legacy data inconsistent with the new completion system
   - OR conditionally render only if CompletionExportGatePanel fails

2. **Fix auth token bug** (see Task 1)
   - Replace `localStorage.getItem('firebase_token')` with `getAuthHeaders()`

3. **Remove SmartSuggestionsPanel** or wire to actual AI service
   - Currently renders empty "No pending suggestions" message
   - TODO comment indicates not implemented
