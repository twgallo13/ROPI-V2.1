**Count**: 69 attributes

Used by SDK helper functions:
- `isExportable(id)` - Check exportability
- `isInternalOnly(id)` - Check internal-only flag
- `getAttributesForTarget(target)` - Channel-specific filtering

### Firestore Keys (Dynamic)
**Path**: `settings/attributes/keys/{attributeId}`
**Count**: 119 documents

Loaded by `attributeValidator.loadRegistryMap()` for:
- Import validation
- Export attribute resolution
- Runtime attribute lookups

### Firestore Doc (Legacy)
**Path**: `settings/attributes`
**Count**: 69 fields

Appears to be a legacy flat structure, possibly pre-migration format.
Not actively used by completion engine.

## Completion Engine Data Flow

```
completionDrivenExportReadiness.ts
       │
       ▼
loadAttributeRegistryForCompletion()
       │
       ▼
loadExportableAttributes()  [exportService.ts]
       │
       ├─► loadRegistryMap()  [attributeValidator.ts]
       │         │
       │         ▼
       │   Firestore: settings/attributes/keys/*
       │         │
       │         ▼
       │   Map<string, AttributeDefinition>
       │
       └─► isExportable(id)  [SDK]
                 │
                 ▼
           SDK: attributeRegistry.json
```

### Issue Identified

The `loadExportableAttributes()` function:
1. Loads ALL 119 attributes from Firestore
2. Filters using `isExportable(id)` from SDK (which only knows 69)
3. Attributes in Firestore but NOT in SDK are filtered out!

This means **50 Firestore-only attributes are silently excluded** from exports.

## Findings

### Finding 1: SDK vs Firestore Mismatch
- SDK has 69 attributes
- Firestore has 119 attributes
- 50 attributes exist only in Firestore

### Finding 2: Silent Filtering
The `isExportable(id)` SDK check silently filters out attributes not in SDK.
This may cause:
- Missing required attributes in completion evaluation
- Inconsistent export column lists
- Attributes visible in UI but not in exports

### Finding 3: No Sync Mechanism
There is no automatic sync between SDK registry and Firestore.
They can diverge without warning.

---

## Recommendation (for follow-up LP)

1. **Audit attribute mismatch**
   - List 50 attributes in Firestore not in SDK
   - Determine if they should be added to SDK or removed from Firestore

2. **Consider single source of truth**
   - Either SDK-only (version-controlled) OR Firestore-only (dynamic)
   - Not both with filtering

3. **Add validation/warning**
   - Log warning when Firestore attribute not found in SDK
   - Prevent silent data loss
