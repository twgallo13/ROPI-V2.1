## Summary

The UI renders per-site export options in two places:
1. **ExportPage.tsx** — allows site selection in export UI (ropi-web, shiekh, karmaloop, mltd)
2. **CompletionExportGatePanel.tsx** — displays per-site blocking status via `siteStatus` array

The decision to render per-site is driven by:
- The presence of `operatorExplanation.siteStatus[]` in the completion API response
- UI logic that maps `siteStatus` array to UI elements (site buttons, missing attributes per site)

## D. API Contract — What the UI Expects

The UI expects the completion API (`/api/products/:id/completion`) to return:

```typescript
{
  ready: boolean,
  completionPct: number,
  threshold: number,
  hasBlockingSites: boolean,
  blockingReasons: Array<{...}>,
  operatorExplanation?: {
    summary?: string,
    blockingIssues?: string[],
    completionBreakdown?: Array<{
      segmentId: string,
      segmentName: string,
      score: number,
      weightPct: number,
      missingAttributes: string[]
    }>,
    siteStatus?: Array<{
      site: string,
      blocked: boolean,
      reason?: string,
      missingAttributes?: string[]
    }>,
    actionRequired?: string[]
  }
}
```

**Key field:** `operatorExplanation.siteStatus[]` drives the per-site UI. If this array is present and non-empty, the UI renders site-by-site export readiness.

## E. Evidence of Per-Site Export Scope

**ExportPage.tsx line 36-42:** The export API is called with a single `site` parameter. This means:
- Each export request is scoped to one site at a time.
- The user must select a site from the dropdown before exporting.
- There is no "export all sites" or "global export" option in the UI.

**Export API request body:**
```json
{
  "site": "ropi-web",
  "format": "csv",
  "limit": 100,
  "includeMeta": true
}
```

This confirms that exports are **per-site** in the current implementation.

## F. Conclusion

**Per-site UI rendering decision points:**

1. **ExportPage.tsx L169-189:** Hardcoded site dropdown (ropi-web, shiekh, karmaloop, mltd)
2. **ExportPage.tsx L36-42:** Export POST body includes `site` parameter (single site per export)
3. **CompletionExportGatePanel.tsx L200-227:** Renders `siteStatus[]` as per-site accordion when present
4. **ExportBlockedModal.tsx L106-115:** Modal shows per-site blocking details when `siteStatus[]` exists

**Current contract:** The UI depends on `operatorExplanation.siteStatus[]` to display per-site export readiness. If this field is removed or replaced, the UI will not render site-specific details.

**RetailOps implication:** For RetailOps global export, we need to:
- Either remove `siteStatus[]` and render product-level readiness only
- Or preserve `siteStatus[]` as optional and add a product-level `productReadiness` field that the UI checks first
