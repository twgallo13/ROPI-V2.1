# Site Gating Evidence — extractSelectedSites() Behavior

## Summary

The `extractSelectedSites()` function determines which sites a product targets. If the function returns an empty array `[]`, the product is **immediately blocked** from export regardless of completion score. This implements a mandatory site-selection gate.

---

## A. Function Definition

**File:** packages/api/src/services/completionDrivenExportReadiness.ts
**Lines:** 426-450

```typescript
/**
 * Extract selected sites from product document
 * Precedence: websites → sites → website (string) → attributes.website
 * LP-export-completion-fix-1.0.0: Added attributes.website support for CSV imports
 * @exported for testing
 */
export function extractSelectedSites(product: ProductDocument): string[] {
  // LP-export-site-extract-1.0.0: Precedence order:
  // 1. product.websites (array)
  // 2. product.sites (array)
  // 3. product.website (string)
  // 4. product.attributes.website (array or string)
  
  if (Array.isArray(product.websites) && product.websites.length > 0) {
    return product.websites;
  }
  if (Array.isArray(product.sites) && product.sites.length > 0) {
    return product.sites;
  }
  if (product.website && typeof product.website === 'string' && product.website.trim()) {
    return [product.website.trim()];
  }
  
  // LP-export-completion-fix-1.0.0 + LP-export-site-extract-1.0.0:
  // Support attributes.website as array or string (CSV imports)
  const attrSite = product.attributes?.website;
  if (Array.isArray(attrSite) && attrSite.length > 0) {
    return attrSite;
  }
  if (typeof attrSite === 'string' && attrSite.trim()) {
    return [attrSite.trim()];
  }
  
  return [];
}
```

## D. Why This Gates Export

The site-selection gate serves two purposes:

1. **Data Validation:** Ensures products have a valid `website` field (required for RetailOps export mapping)
2. **Per-Site Evaluation Requirement:** The completion engine evaluates site-specific attributes (e.g., `description_ropi_web`, `seo_title_shiekh`) and requires `selectedSites[]` to know which sites to check

**Current behavior:** Site selection is **mandatory** for export. Products without sites cannot pass the export gate.

---

## E. RetailOps Implication

For RetailOps global export, this creates a problem:

- **RetailOps does not care about per-site attributes** (no site-specific descriptions)
- **RetailOps only exports to one destination** (RetailOps CSV feed)
- **Products should be export-ready based on product-level attributes only** (sku, name, brand, category, class, department, etc.)

**Current blocker:** Even if a product has perfect core/classification attributes, it will be blocked if it has no `website` field set.

**Proposed solution:**
- Add a `mode` field to the readiness config: `GLOBAL` or `SITE_SCOPED`
- In `GLOBAL` mode:
  - `extractSelectedSites()` returns a synthetic site list (e.g., `["global"]`) if product has no sites
  - Completion engine evaluates **only product-level attributes** (not site-specific)
  - siteStatus[] is not generated (or generated as empty array)
- In `SITE_SCOPED` mode:
  - Keep current behavior (require sites, evaluate per-site)

## G. Conclusion

**Site gating is absolute:** Products without sites cannot be evaluated or exported in the current implementation.

**Why this matters for RetailOps:**
- RetailOps export is **global** (not per-site)
- Products should be ready based on **product-level completeness** (core + classification attributes)
- The `website` field is currently **required**, but it's not semantically relevant for RetailOps (which exports to a single CSV feed)

**Target design must address:**
- How to evaluate products without `website` field in GLOBAL mode
- How to compute product-level readiness (ignoring site-specific attributes like `description_<site>`)
- How to preserve per-site evaluation for other tenants (non-RetailOps)
