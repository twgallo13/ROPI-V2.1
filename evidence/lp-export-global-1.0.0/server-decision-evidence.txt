## Summary

The server generates `siteStatus[]` in the `operatorExplanation` field by:
1. Extracting selected sites from the product document via `extractSelectedSites()`
2. Evaluating completion per-site via `evaluateCompletion()` engine
3. Mapping site-blocking reasons to `siteStatus[]` array in `generateOperatorExplanation()`

The decision to include per-site evaluation is driven by the presence of `product.websites` / `product.sites` / `product.website` fields and the completion engine's per-site blocking logic.

## B. extractSelectedSites() — Site Discovery Logic

**File:** packages/api/src/services/completionDrivenExportReadiness.ts
**Lines:** 426-450

### Code Citations

**Lines 426-450:** Site extraction precedence
```typescript
/**
 * Extract selected sites from product document
 * Precedence: websites → sites → website (string) → attributes.website
 * LP-export-completion-fix-1.0.0: Added attributes.website support for CSV imports
 * @exported for testing
 */
export function extractSelectedSites(product: ProductDocument): string[] {
  // LP-export-site-extract-1.0.0: Precedence order:
  // 1. product.websites (array)
  // 2. product.sites (array)
  // 3. product.website (string)
  // 4. product.attributes.website (array or string)
  
  if (Array.isArray(product.websites) && product.websites.length > 0) {
    return product.websites;
  }
  if (Array.isArray(product.sites) && product.sites.length > 0) {
    return product.sites;
  }
  if (product.website && typeof product.website === 'string' && product.website.trim()) {
    return [product.website.trim()];
  }
  
  // LP-export-completion-fix-1.0.0 + LP-export-site-extract-1.0.0:
  // Support attributes.website as array or string (CSV imports)
  const attrSite = product.attributes?.website;
  if (Array.isArray(attrSite) && attrSite.length > 0) {
    return attrSite;
  }
  if (typeof attrSite === 'string' && attrSite.trim()) {
    return [attrSite.trim()];
  }
  
  return [];
}
```

**Behavior:**
- Checks 4 possible product fields for site selection (precedence order)
- Returns array of site strings
- If no sites found, returns empty array `[]`

**Implication:** Products without any site field set will return `[]`, which blocks export at line 330-336:
```typescript

  return createBlockedReadiness(
    'No sites selected for product',
    [],
    completionRules,
    evaluationTimestamp,
    productSnapshot
  );
}
```

## F. Why Exports Are Per-Site Today

**Evidence:**

1. **Site extraction is mandatory:** Lines 327-336 block export if no sites selected
2. **Completion engine requires sites:** Line 341-343 passes `selectedSites` to engine
3. **siteStatus is always generated:** Lines 563-580 map `selectedSites` to `siteStatus[]`
4. **UI consumes siteStatus:** Frontend (ExportPage.tsx) renders per-site dropdown and panel shows per-site status

**Causal chain:**
```
Product doc → extractSelectedSites() → selectedSites[]
                                           ↓
                                    evaluateCompletion(selectedSites)
                                           ↓
                                    siteBlockingReasons[]
                                           ↓
                                    generateOperatorExplanation()
                                           ↓
                                    siteStatus[] in API response
                                           ↓
                                    UI renders per-site UI
```

## H. Conclusion

**Server decision points for per-site evaluation:**

1. **extractSelectedSites() (L426-450):** Determines which sites to evaluate (4-field precedence)
2. **evaluateCompletion() (L341-346):** Passes `selectedSites` to completion engine, returns per-site blocking reasons
3. **generateOperatorExplanation() (L563-580):** Maps `selectedSites` to `siteStatus[]` array in response
4. **Blocking logic (L330-336):** Products with no sites are blocked immediately

**Current contract:** The API always returns `siteStatus[]` if sites are selected. The `ready` flag is affected by `hasBlockingSites` (site-level blocking).

**RetailOps implication:** For global export, we need to:
- Compute product-level completion **ignoring site-specific attributes** (core + classification attributes only)
- Add `productLevelReadiness` field to response (ready/completionPct/blockingReasons)
- Keep `siteStatus[]` as optional (for non-RetailOps tenants)
- Add a `mode` field (GLOBAL | SITE_SCOPED) to signal which contract is in use
