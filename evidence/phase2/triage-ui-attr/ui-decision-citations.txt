## Key Findings

### What Controls UI Rendering?

**Primary Control Variable:** `completion.mode` field from API response

**Decision Flow:**
1. Frontend fetches `/api/products/:id/completion`
2. Response includes optional `mode` field ('GLOBAL' | 'SITE_SCOPED')
3. Frontend defaults to `'SITE_SCOPED'` if `mode` absent: `completion?.mode ?? 'SITE_SCOPED'`
4. UI renders based on mode:
   - `mode === 'GLOBAL'` → GlobalModeCard + GLOBAL badge + hidden site selector
   - `mode !== 'GLOBAL'` (including undefined) → Legacy panel + site selector visible

### Why Legacy Panel Appears

**Root Cause:** API response is **not returning `mode: 'GLOBAL'`** in `/api/products/:id/completion`

**Possible Reasons:**
1. Feature flag `settings/exportSettings.exportGlobalMode` is disabled or absent
2. Backend engine not evaluating in GLOBAL mode
3. Backend not setting `mode` field in response
4. Firestore settings document missing or misconfigured

### Next Investigation Required

To determine why `mode` is missing from API responses, need to:
1. Check actual API responses (capture network traces)
2. Verify Firestore feature flag state
3. Examine backend code that sets `mode` field
4. Check if backend conditions for GLOBAL mode are met
