## 5. Analysis of Warnings

### Warning: CONDITION_UNKNOWN_ATTRIBUTE for 'rics_category'

**Finding:** All 3 rules use `attributes.rics_category` as a condition field, which is not found in the attribute registry.

**Investigation:**
- Field path: `attributes.rics_category` (canonical format ✓)
- Used in condition matching only (not as target)
- All rules check if rics_category contains specific tokens

**Explanation:**
The `rics_category` field appears to be a **source import field** or a **custom field** that exists in import data but is not formally defined in the attribute registry. This is a common pattern for:
1. Source-specific fields from vendor data
2. Temporary fields used for rule matching
3. Fields awaiting formal registry definition

**Risk Assessment:**
- ⚠️ **Low Risk:** Field is only used for condition matching (read-only)
- ✅ **Not a blocker:** Rules are not trying to write to this field
- ✅ **Canonical format:** Field uses proper `attributes.` prefix
- ℹ️ **Runtime behavior:** If field missing on product, condition will not match (safe fallback)

**Recommendation:**
1. **Option A (Recommended):** Add `rics_category` to the attribute registry with proper definition
   - Type: `string` or `enum` with allowed values
   - Mark as `import_only: true` if not exported
   - Add documentation about source

2. **Option B:** Allow source fields in conditions with `source.` prefix
   - Update rules to use `source.rics_category` instead
   - Audit script already allows `source.*` prefix without registry validation

3. **Option C:** Accept warning and document
   - Rules work correctly in production
   - Field exists in import data
   - No critical impact on functionality

**Decision Required:** Lisa to decide whether to add `rics_category` to registry or change prefix.

## 9. Technical Notes

### Audit Script Features
- **Dry-run only:** No modifications made to rules
- **Registry integration:** Loads live attribute definitions from Firestore
- **Structured output:** JSON and text artifacts for programmatic analysis
- **Severity classification:** Critical (blocker) vs. Warning (review) vs. Info (suggestion)
- **Exit codes:** 0=pass, 1=error, 2=critical flags

### Validation Logic
- **Prefix normalization:** Accepts `attributes.`, `observation.`, `meta.`, `source.`, `tags.`
- **Registry lookups:** Validates attribute_id, checks internalOnly, exportable flags
- **Enum validation:** Checks allowed_values, handles synonyms
- **Template handling:** Skips validation for `{{...}}` template values (runtime)

### Limitations
- **Source fields:** Script does not validate source.* fields against schema
- **Runtime templates:** Cannot validate templated values until runtime
- **Condition logic:** Does not validate AND/OR/NOT condition tree structure
- **Value transformations:** Does not validate custom functions or transformers
