PROBLEM STATEMENT
================================================================================

LP-2.1.4 introduced Firestore rules lockdown for products/* collection.
Emulator smoke tests revealed "Property role is undefined on object" error
when evaluating rules for users without the 'role' custom claim.

Error observed:
  "Property role is undefined on object. for 'create' @ L143"

Root cause: Firestore rules accessing `request.auth.token.role` on tokens
where the 'role' claim does not exist. Even with null checks on auth/token,
accessing a non-existent property throws this error.

================================================================================
SOLUTION IMPLEMENTED
================================================================================

Added ('role' in request.auth.token) checks before accessing .role property
on ALL code paths:

1. isAdmin() function (line 23):
   return request.auth != null 
          && request.auth.token != null 
          && ('role' in request.auth.token)
          && request.auth.token.role == 'admin';

2. requiresEmailVerification() function (line 58):
   return request.auth != null 
          && request.auth.token != null
          && ('role' in request.auth.token)
          && (
            request.auth.token.role == 'admin'
            || request.auth.token.role == 'merch'
            || request.auth.token.role == 'buyer'
            || request.auth.token.role == 'photographer'
          );

3. import_batches collection rules (lines 229, 243):
   || (('role' in request.auth.token) && request.auth.token.role == 'merch')
