SOLUTION IMPLEMENTED (Step 3)

Fix #1: Update firebase.json
----------------------------
Changed:
  "public": "public"
To:
  "public": "packages/web/dist"

Rationale:
- Point Firebase hosting directly to Vite build output
- Eliminates need for intermediate copy step
- Firebase will deploy exactly what Vite produces

Fix #2: Simplify deploy-staging.yml
------------------------------------
Removed:
- 90+ lines of complex "Prepare public directory" logic
- Placeholder HTML fallback
- rsync copy operations

Added:
- Simple "Build packages/web" step
- Explicit verification: checks for packages/web/dist/index.html
- Fails fast if build output not found (no silent fallback)

New Build Step:
```yaml
- name: Build packages/web
  run: |
    set -euo pipefail
    echo "Building packages/web with Vite..."
    pnpm --filter @ropi-aoss/web build
    
    # Verify build output
    if [ ! -f packages/web/dist/index.html ]; then
      echo "::error::packages/web/dist/index.html not found after build"
      exit 1
    fi
    
    echo "✅ Build complete: packages/web/dist ready for deployment"
    ls -lh packages/web/dist/
```

================================================================================
LESSONS LEARNED
================================================================================

1. Always verify build output location matches hosting config
   - Vite default: dist
   - Firebase expected: configured in firebase.json public path
   - Mismatch = deployment of wrong directory

2. Avoid silent fallbacks in deployment workflows
   - Placeholder logic hid the real problem
   - Fail fast is better than deploying placeholders
   - Explicit verification prevents silent failures

3. Check PR dependencies before starting deployment fixes
   - PR #154 (frontend) was required but not merged
   - Deployment can't be fixed without deployable content
   - Merge order matters: source first, then deploy config

4. Simplicity beats complexity in CI/CD
   - Removed 90+ lines of complex logic
   - Replaced with 11 lines of simple build + verify
   - Easier to understand, debug, and maintain

5. Firebase hosting rewrites handle SPA routing
   - All routes return same index.html
   - React Router handles client-side navigation
   - No need for server-side route configuration
