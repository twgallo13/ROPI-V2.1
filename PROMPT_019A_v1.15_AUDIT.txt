#### Added: Setup gcloud & activate service account step

**Purpose**: Properly activate and configure gcloud

**Steps**:
1. Install `google-cloud-cli` if missing
2. Validate `/tmp/sa.json` exists
3. Activate SA: `gcloud auth activate-service-account --key-file=/tmp/sa.json --project=ropi-bccee`
4. Set active account: `gcloud config set account <client_email>`
5. Set project: `gcloud config set project ropi-bccee`
6. Verify: `gcloud auth list --filter=status:ACTIVE`
7. Test: `gcloud auth print-access-token` (capture and measure length)
8. Exit with error if token generation fails

## Technical Notes

### YAML Heredoc Issue Fixed
The diagnostic step initially used a Python heredoc (`<<'PY'`), which caused YAML parse errors because unindented heredoc content is interpreted as root-level keys. Fixed by using `python3 -c` with inline script.

### Why Separate Diagnose and Setup Steps
1. **Diagnose**: Captures pre-activation state, tests activation without side effects
2. **Setup**: Performs actual activation with error handling

This separation helps identify whether the problem is:
- **Before activation**: Missing files, invalid secrets, gcloud not installed
- **During activation**: `gcloud auth activate-service-account` fails
- **After activation**: Account not set as active, token generation fails

### Credential Flow
```
Secret (base64) → Decode → /tmp/sa.json → gcloud activate → Active account
                                        ↓
                            GOOGLE_APPLICATION_CREDENTIALS → Node SDK
```

## Troubleshooting Guide

### If "gcloud not installed" in diagnose step:
- Setup step should install it automatically
- Verify Ubuntu runner has apt access

### If "/tmp/sa.json NOT FOUND":
- Decode step failed to create file
- Check GCP_SA_KEY_BASE64 secret exists and is valid base64

### If "GCP_SA_KEY_BASE64 UNSET":
- Secret not configured in staging environment
- Go to: Settings → Environments → staging → Secrets

### If "gcloud activate failed":
- Check error output in diagnostic logs
- Likely invalid service account JSON format
- Verify JSON has required fields: `client_email`, `private_key`, etc.

### If "print-access-token failed":
- Service account activated but can't generate tokens
- Check IAM permissions in GCP console
- SA needs `iam.serviceAccountTokenCreator` or similar

### If Node script fails:
- Check GOOGLE_APPLICATION_CREDENTIALS is set
- Verify applicationDefault() can read /tmp/sa.json
- Check Firebase Admin SDK permissions (needs `firebaseauth.users.update`)
