2.1 Backend Service Layer
--------------------------
packages/api/src/services/productCommitService.ts (~320 lines)
  Purpose: Core business logic for converting import rows to products
  
  Key Functions:
  - convertRowToProduct(row): Maps ImportEngineRow to Product with statusFlags
  - processRow(row, db, userId): Handles single row (create/update/skip)
  - processImportBatch(batchId, userId): Main orchestrator with counters
  - getBatchStatus(batchId): Status polling endpoint
  
  Business Rules:
  - Idempotent: Re-running processImportBatch updates counters accurately
  - Validation blocking: Rows with errors get importOutcome='skipped_validation_error'
  - Status flags: All products initialize with ready_for_export=false, uploaded_to_ro=false
  - Create vs Update: Checks product existence, preserves createdAt on updates

2.2 Backend API Endpoints
--------------------------
packages/api/src/endpoints/processImportBatch.ts (~95 lines)
  Purpose: HTTP handlers for commit operations
  
  Endpoints:
  - POST /processImportBatch (admin-only, CORS-enabled)
    Request: { batchId: string }
    Response: BatchProcessResult with counts and results array
  
  - GET /importBatchStatus (admin-only, CORS-enabled)
    Request: ?batchId=xxx
    Response: { status, createdCount, updatedCount, blockedCount, processedAt }

7. ARCHITECTURE NOTES
================================================================================

7.1 Two-Phase Commit Flow
--------------------------
Phase 1: CSV Upload → Row Creation
  User uploads CSV → importCSV Cloud Function → import_batches/{id}/rows
  
Phase 2: Row Validation → Product Commit
  User clicks Confirm → processImportBatch Cloud Function → products/{id}

BENEFITS:
- Clear separation of parsing/validation vs. product creation
- Enables batch review before commit
- Supports batch-level rollback (delete batch without touching products)

7.2 Idempotency Design
-----------------------
Re-running processImportBatch(batchId) is safe:
- Product updates preserve createdAt timestamp
- Counters recalculate from scratch (not incremental)
- importOutcome updated on each row

USE CASE: Retry logic for network errors or user corrections

7.3 Navigation Flow
-------------------
Import Manager → Batch Detail → W2 Product Editor

Path: /imports/batch/{batchId} → /products/{productId}

Link Component:
  <Link to={`/products/${row.meta.productId}`}>
    View Product (Created) →
  </Link>

W2 Product Editor:
- Pre-populated with imported data
- User can review/edit before exporting to RO
- Status flags guide workflow (ready_for_export, uploaded_to_ro)
